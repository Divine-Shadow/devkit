# Source-bound preserving native preparation

Normal preparation can consume the optional retainedHistory manifest, manifest
digest, bundle digest and thread ID from the immutable selected GUI projection.
All four fields are required together and must match the selected native lane.
They cannot be selected through environment, caller paths or reset arguments.

Installation requires the owning lifecycle boundary and absent selected native
socket. It validates the complete pinned three-member cold family, native goals
schema/migrations and same-thread rollout. It copies only original goals and
missing rollout, retaining the previous business-empty goals inode in journal
custody. Existing current state and independent tables stay intact; normal
native resume performs indexing. Credentials and public configuration are not
part of history projection. Software-only preparation still skips credential
hydration and legacy state migration.

Prepared journal recovery revalidates sidecars, custody and absence before
continuing. File/directory syncing and no-overwrite publication protect the
original source and previous goals. An interrupted unjournaled validation stage
is refused without automatic cleanup or current-goals retirement. Committed
preparation performs a no-write prefix/custody check compatible with an active
native owner and suffix appends. It does not restore an altered later goal.

Reset capture and retirement never invoke this projection. Cold original bytes
and inodes stay read-only. Runtime must establish the supported idle and consumer
handoff before the existing typed software-only forced restart. Source fixtures
and publication do not authorize activation or prove live model/completion.

## Available evidence is distinct from finite preparation

The current Management custody policy separately admits v4 unavailable GUI
references when the exact captured SQLite/reference and every available history
byte are preserved with canonical physical absence and stable source proof.
Archive status is a bounded observation, never a resumability or reset warrant.
V4 is explicitly incomplete/unclassified/ineligible for resume; it does not
restore a missing body. The finite preparation projection on this page remains
v2-only. Existing v3 archived-reference readers remain strict. Query/integrity,
physical ambiguity and races still refuse. No row edit, import, bypass or retained
history pruning is added. See the [source decision](../decision-framework/governance_decisions/20261016_available_gui_reference_v4_custody.md).
