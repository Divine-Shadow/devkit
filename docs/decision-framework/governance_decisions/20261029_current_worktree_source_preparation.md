# Prepare current accepted-source metadata without integrating a writer

## problem

Product receiving correctly requires actual remote main and origin/main to
agree before loading accepted policy. Ordinary publication can advance main
after writer construction. Selected Devkit preparation constructs an empty
lane; prefix preparation also provisions homes and rewrites its manifest.
Neither supplies a bounded refresh for an existing signed GUI task/root.

The affected frontend writer shares Agent1's lane-owned common repository;
the clean producer is a standalone clone at its exact GUI child root. These
are distinct admitted forms, not interchangeable paths.

## options

Use prefix construction for its fetch side effect; weaken Product equality;
have callers mutate refs; or expose the missing source preparation through
Devkit's existing package-owned acquisition mechanics.

## selection_rationale

Add `devctl -p dev-all native prepare --current-worktree --source-only
--repo ouroboros-ide --format json`. Derive geometry/origin from immutable
runtime configuration and the fixed GUI projection. Require the current v4
consumer and exact protected managed transport. Admit either a registered
linked writer sharing the exact marked lane common repository, or a standalone
single-worktree clone at the fixed GUI child geometry and declared origin.

The current consumer's mounted immutable system profile selects its existing
Devctl connector helper. The preparation artifact does not require that helper
to have its own new package path: delivery preserves the same app-server and
its protected connector. Exact SSH/trust/config, helper, project and socket
recipe remain checked; no replacement transport or caller selector is added.

Acquire the observed remote commit without a destination/refmap, FETCH_HEAD,
tags, pruning, submodules or auto-maintenance. Explicitly check old tracking
commit ancestry without replacement-object interpretation, then prepare Git
update-ref's expected-old-value transaction on origin/main. Inspect direct
versus symbolic shape while that transaction holds Git's no-deref ref lock;
commit only for a direct ref. An expected OID alone can match a concurrently
created symbolic ref, so checking shape before acquisition is insufficient.
Fixed fetch flags alone do not establish non-rewind. A concurrent direct or
symbolic change refuses rather than being overwritten. EOF aborts an uncommitted
transaction and releases its lock; no caller lock-file cleanup occurs. Objects
may be acquired before refusal. A lost commit reply has unknown disposition
and requires reading actual tracking before retry. This is acquisition, not
integration or approval.

Correctness comes from explicit source/geometry and ancestry/CAS contracts;
real-Git consequence tests verify preservation and racing/non-forward cases.
No source selection flag, shell recipe or general custody framework is added.

## safety_checks

Preserve HEAD, index, files/modes, other refs/worktrees, homes, manifests,
history, attribution, existing signatures and registered roots. Reject caller
repository/config selectors, foreign origins/common repositories, redirected
geometry, legacy grafts, URL rewrites, custom reference hooks, missing/noncommit tracking refs and
replacement transport. No reset, cleanup, config repair or salvage occurs.

After preparation Product must reevaluate current policy, eligibility and
admission at the same binding. A newer policy may legitimately refuse; a
remote race may require another ordinary preparation. Source qualification
does not establish actual Runtime delivery or business acceptance.

## verification

Real-Git tests cover linked/shared and standalone writers, staged and unstaged
candidate bytes/modes, HEAD/index/FETCH_HEAD/other-ref preservation, remote
advance, rewind, divergence and a concurrent tracking transaction. Parser and
replacement-ancestry, concurrent symbolic replacement, aborted-lock cleanup and
prepared-lock exclusion are checked using real Git. Parser and
transport tests reject alternate selectors and command suffixes. Complete
normal Devkit CI, independent review and immutable package qualification are
required before publication and receiving delivery.

## rollback_plan

Use a reviewed source revert and ordinary publication/composition. There is no
local ref rollback or automatic rewrite of previously prepared consumers.

## decision_scope

Root's existing canonical source-preparation assignment. Runtime retains
actual effects/delivery; Product authors retain implementation and admission.
The qualified WSL6ef image and prior frontend preparation remain accepted.
Agent2's directory-shape provisioning issue remains a separate obligation.
