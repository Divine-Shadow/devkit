# Proxy-only managed endpoint isolation

## problem
Normal Terraform Agent1 full preparation refused an accepting shared egress listener before the AWS callback. Its ownership/namespace/executable remain unverified after actual denied kernel reads. Source nevertheless exposes a discriminating defect: withManagedRuntimeEndpoints and isolateRuntimeExecutionPlan omit per-invocation isolation whenever no PostgreSQL endpoint is present, although their existing lower helper supports proxy-only plans. Current1F and the immutable source behind the reported1d8 package token have byte-identical relevant functions. That token comparison does not prove live ownership.

## options and rationale
Do not infer staleness, weaken unknown-listener refusal, stop another owner, or add unverified reuse. Apply the existing isolated endpoint mechanism to managed proxy-only preparation and execution. The exclusive-listener warrant remains valid for the endpoint being created. The source repair makes each invocation establish its own endpoint instead of attempting exclusive creation at a retained shared endpoint. Existing allowlist, upstream policy, required bind and cleanup checks remain authoritative.

## verification

Overlapping invocation lifetimes get distinct simultaneously live endpoints and independent cleanup. Execution uses its existing isolation/start/cleanup helpers twice with retained shared state. An actual blocked CONNECT confirms the same allowlist enforcement. Missing/duplicate binds, unknown listener refusal, dry-run and existing PostgreSQL regressions remain fail-closed. Full affected native qualification, independent review and normal supplying publication are separate from actual Runtime adoption and Auth receipt assessment.
