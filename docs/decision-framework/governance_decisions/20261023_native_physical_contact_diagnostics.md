# Metadata for transient foreign physical contacts

Root authorized this bounded evidence change after Local2 operations refused
different unowned physical touchers; later PID absence did not establish their
owner or a custody defect. The accepted native physical-proof and Codex package
changes remain the base. No lifecycle retry or ownership relaxation follows.

Extend the existing read-only `native plan --process-custody-observation` report
with at most 32 physical contacts from its same bounded process inventory. Reuse
the reset guard's exact touch routine and pinned ancestry walk. The optional
metadata sink cannot affect its boolean/error result. Report all declared roots
that are the same object at the first matched physical ancestor; do not infer
outer roots from lexical spellings. Empty, incomplete and truncated reports
never prove absence. The original marked alias observations remain available.

At the existing refusal snapshot, retain one bounded metadata stderr record
separately from the unchanged 512-byte refusal. Include PID/start/parent-start,
revalidated process/namespace objects and comparisons, matched root class/object,
and executable object. Export an executable path only for strict immutable Nix
store bin/libexec grammar with exact host-object equality and revalidation. User
paths, raw argv, environment values and heuristic invocation labels are absent.
Unavailable/unstable evidence remains explicit; labels grant no custody.

The alternative was another destructive attempt to collect ephemeral metadata
or a new monitoring endpoint. This uses the existing read-only interface and
refusal, prioritizing correct physical identity, verifiability and preservation
of all process/stop/history/reset gates. Source review and normal required CI
remain prerequisites for publication; runtime supply/receiving stays Root-owned.

Tests cover direct and deeper aliases, same-object overlapping roots, child and
parent identity/namespace/executable/selected-object drift, unavailable metadata,
unmarked and unreadable-environment contacts, cap semantics and privacy. No
capture/SQLite-reader change is included. Owning-source revert followed by normal
immutable convergence is the rollback route.
