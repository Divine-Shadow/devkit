# Same-lane custody evidence in a missing-rollout refusal

Current status: this historical record describes its original v2/v3 source and
actual refusals. Management subsequently adjudicated the distinct [v4 available
GUI-reference class](20261016_available_gui_reference_v4_custody.md). V2/v3 remain
strict; no old refusal is retconned and no Runtime success follows from the new
source contract.

## problem

Local1 standard reconstruction `op-f9c1877a92c944ea33137c0a79b9eca1`
stopped the selected runtime and then refused mandatory cold capture because an
unarchived SQLite GUI reference has no corresponding current rollout. Reset
apply and fresh construction were not reached. Existing failure observations
establish current absence, not whether the normal lane custody contains an
earlier retained member. A bounded manifest-name request through the installed
controller was actually refused before an operation ID; arbitrary private-file
inspection is not an available substitute.

## options

Keep an unresolved request for an unnamed provider, expose an arbitrary history
reader, weaken capture or archive the row, or extend the existing owning capture
provider's content-free refusal with bounded same-lane custody evidence.
Select the last option. This maintains the existing producer and lifecycle
effect rather than introducing a consumer recovery tool.

## selection_rationale

Under the Management Source commission and its
`docs/decision-framework/tradeoff_decision_framework.md`, preserve correctness,
verifiability, safety and truthful evidence before speed. The provider already
owns private history capture and validation. It can inspect its canonical lane
custody while keeping session bodies inside that institution. The selected
snapshot requirement and unavailable-archived-reference eligibility do not
change. No new grant, trust, Auth, sandbox or policy mutation follows.

## safety_checks

On the existing missing-member refusal only, inspect a bounded set of normal
generation manifests beneath the exact selected lane custody root. Use held
directories and no-follow reads. Require matching source lane/home geometry;
accept only the exact mapped history member and matching session identity.
Report actual manifest/member digests, coverage limits and fixed diagnostic
classes, never session bodies, titles, goals, credentials or arbitrary paths.
Reuse the existing rollout validator. A matching member is inventory evidence,
not complete-bundle validation, restoration authority or resumability.

Missing, malformed, foreign, changed, symlinked, oversized and incomplete
evidence stays explicit. Observation failure cannot replace the original
refusal. Capture still publishes no successful generation and resets remain
blocked. No restoration, import, row edit, automatic archive, reset bypass or
backup pruning is added.

## verification

Exercise the real capture path with a previously captured same-lane member,
absent custody, foreign source geometry, tampered member, wrong identity,
symlinks, partial generations and bounded coverage. Verify exact source and
custody bytes remain unchanged, private content never enters diagnostics and
the original missing-member refusal remains terminal. Run the relevant full
Devkit gates and independent review, publish normally, then supply its exact
immutable package/closure through WSL composition. Runtime retains deployment,
the actual inventory-producing lifecycle operation, custody and retry. Only
its real result establishes whether Local1 has a retained matching member.

## Availability boundary

The actual standard route drains in Fleet before Devkit's stop, absence check,
cold capture, second absence check and destructive apply. Cold consistency
requires capture after absence; it does not require discovering a determinable
missing reference only after stopping a usable consumer. Add a bounded
metadata preflight to the same source-owned native reset command and invoke it
under Fleet's existing target lease before drain. It privately copies only the
SQLite family for read-only validation, checks mapped member presence and the
unchanged archived-reference rule, and never creates an accepted snapshot.
The normal post-stop snapshot remains mandatory and can still refuse a later
race. The separate preserving-start path can recover availability after an
already stopped attempt; no automatic restart of old governed execution is
introduced. Neither a dated filename nor this post-stop observation proves when
the original rollout became unavailable.

## rollback_plan

Withhold publication on privacy, admission, preservation or native-test failure.
Use a reviewed source revert/correction if the observation is defective. Keep
all original failed receipts and retained history. The independent ordinary
parent bootstrap/preserving-preparation route remains available for Runtime
to qualify; this diagnostic does not become a blanket Writer admission gate.

## decision_scope

Maintenance of the existing Devkit cold-capture failure evidence. It does not
select or restore a backup, change snapshot eligibility, implement the optional
SBT interface, or claim reliable Writer SDK/CI/reap/later-parent-reuse acceptance.
