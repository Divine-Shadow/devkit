# Preserve broker observation failure

## problem

An actual ordinary Writer launch failed its shared broker prerequisite. Existing
inspection converts a failed selected observation into a different-process claim,
so the owner cannot distinguish failed evidence supply from mismatching identity.

## options

1. Preserve the existing observer's checked result through readiness inspection.
2. Add a new general host observer or raw process probing path.
3. Treat every false result as a proven different process and keep retrying.

## selection_rationale

Choose option 1. Error-returning inspection and the fixed source-selected helper
already own this boundary. Preserve their failure without expanding capability
or weakening identity, lifecycle, byte or time guards. This supplies honest
evidence for the existing recovery owner. It does not make the launch successful.

## safety_checks

First reproduce the classification bug using fresh owned helper/metadata
fixtures. Test execution failure, timeout, malformed and excessive output,
successful exact and mismatching tuples, and unchanged metadata on refusal.
Run independent review and complete ordinary source gates/publication. Do not
inspect, signal or control the actual broker or uncertain Local8 attempt.

## rollback_plan

Retain the candidate and actual failing evidence. Publish any forward correction
or revert through the same source gates; do not patch a consumer, bypass its
guard, or erase original operation disposition.

## decision_scope

Narrow maintenance of Devkit's existing station observation and readiness
diagnostics. Source1 supplies source/Nix; Runtime owns effects and Environment
ordinary receiving. Apply the [Tradeoff Decision Framework](../tradeoff_decision_framework.md).
